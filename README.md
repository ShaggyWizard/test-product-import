# Импорт товаров из .xlsx

Тестовое задание: загрузка товаров из Excel в БД через **Slim + Doctrine** и **Angular**, асинхронно через **RabbitMQ**.

- Импорт: файл → очередь → воркер. Плохие строки не останавливают импорт и попадают в отчёт.
- Повторный импорт обновляет товары по `external_code`, дублей нет.
- Картинки скачиваются на сервер, по одному файлу на ссылку.
- Список товаров с серверной пагинацией, поиском и фильтром цены (NgRx). Карточка с атрибутами и фото.
- Вход по JWT, Swagger, 52 теста PHPUnit, 6 e2e на Playwright, PHPStan level 8, CI.

## Быстрый старт

Нужны Docker и make (на Windows — Git Bash или WSL; без make команды из `Makefile` можно выполнить вручную).

```bash
make init
```

`make init` копирует `.env.example` в `.env`, собирает образы, поднимает сервисы и применяет миграции. Первая сборка — 3–5 минут.

| Что | Адрес |
|---|---|
| Приложение | http://localhost:8080 — вход `admin` / `admin` (меняется в `.env`) |
| Swagger UI | http://localhost:8080/api/docs |
| Health check | http://localhost:8080/api/health |
| RabbitMQ | http://localhost:15672 — `app` / `app_secret` |

Дальше: «Импорт» → выбрать `docs/import-example.xlsx` → «Импортировать». Через пару секунд — 40 товаров и отчёт.

Тестовые данные без файла: `make seed` (30 товаров с атрибутами и картинками).

## Сервисы Docker

| Сервис | Образ | Роль |
|---|---|---|
| `app` | `backend/Dockerfile`, стадия `prod` | PHP 8.3 FPM, Slim API |
| `worker` | тот же образ | `messenger:consume async` — выполняет импорт из очереди |
| `nginx` | `frontend/Dockerfile` | Собранный Angular + прокси `/api` в PHP-FPM, раздача `/media` |
| `db` | `postgres:16-alpine` | База данных |
| `rabbitmq` | `rabbitmq:3.13-management` | Брокер сообщений |

Оба Dockerfile многостадийные: зависимости и сборка — в отдельных стадиях, в итоговом образе только то, что нужно для работы. Все переменные окружения описаны в `.env.example`.

## Как устроен импорт

```
Браузер ──POST /api/import──▶ app: проверка файла → сохранение → import_jobs (pending) → сообщение в RabbitMQ ──▶ 202 + id
   │                                                                                         │
   └──GET /api/import/{id} раз в секунду (прогресс, отчёт)                                    ▼
                                                     worker: читает xlsx → по строке: проверка → картинки → транзакция
```

1. **Проверка файла** (`ImportUploadValidator`): расширение `.xlsx`, размер до 10 МБ, тип по содержимому (zip с `xl/workbook.xml`), а не по имени.
2. **Rate limit**: 5 загрузок в минуту с одного IP, дальше `429` и `Retry-After`.
3. **Воркер** (`ImportMessageHandler` → `ImportService`):
   - столбцы ищутся по названию, без учёта регистра и пробелов, порядок любой;
   - строка проверяется (`RowMapper`): пустой код или название, цена не числом или ≤ 0, повтор кода в файле → **ошибка**, строка не пишется;
   - картинки качаются **до** транзакции, параллельно (`ImageDownloader`); недоступная картинка → **предупреждение**, товар сохраняется со ссылкой;
   - товар, атрибуты и картинки пишутся **в одной транзакции** (`ProductImporter`), upsert по `external_code`;
   - прогресс сохраняется по ходу, Doctrine очищается пачками по 20 строк.
4. Повторная доставка сообщения не запускает импорт второй раз. При сбое обработчика — 3 повтора с паузой.

Скидка: `(цена продажи − закупочная) / цена продажи × 100`, считается в копейках, при цене 0 — 0.

## API

Полное описание — в Swagger (`/api/docs`, спецификация `/api/openapi.json`). Всё, кроме входа, health и документации, требует `Authorization: Bearer <JWT>`.

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/health` | Приложение и БД живы |
| POST | `/api/auth/login` | Логин и пароль → JWT |
| GET | `/api/products?page=1&limit=20&name=&priceMin=&priceMax=` | Страница товаров |
| GET | `/api/products/{id}` | Карточка: поля, атрибуты, картинки |
| POST / PUT / DELETE | `/api/products[/{id}]` | Ручное создание, изменение, удаление |
| POST | `/api/import` | Загрузка `.xlsx` (multipart, поле `file`) → `202` |
| GET | `/api/import/{id}` | Статус, прогресс, ошибки и предупреждения |
| GET | `/api/import/latest` | Последний импорт |

Ошибки — всегда JSON: `{"error": "...", "details": {"поле": "что не так"}}` (422 — все неверные поля разом, 404, 409, 401, 429).

## Фронтенд

Angular 19, standalone-компоненты с ленивой загрузкой, Angular Material, `strict: true`.

- `src/app/models/` — интерфейсы `Product`, `ProductAttribute`, `ProductImage`, `ImportJob`.
- `src/app/services/` — `ProductService`, `ImportService`, `AuthService`. Компоненты не используют `HttpClient` напрямую.
- `src/app/store/products/` — NgRx для списка: actions `loadProducts` / `loadProductsSuccess` / `loadProductsFailure`, effect через `ProductService`, selectors `selectAllProducts`, `selectProductsLoading`, `selectTotalPages`. Компонент списка читает стор через `async` pipe.
- `src/app/app.routes.ts` — роутинг; `authGuard` (CanActivate) закрывает всё, кроме входа.
- `src/app/auth/auth.interceptor.ts` — добавляет токен; при `401` — выход на страницу входа, при `5xx` — сообщение.
- Страница импорта показывает прогресс (polling раз в секунду) и отчёт. В карточке товара — блок «Последний импорт».

## Тесты и качество

- **PHPUnit** (`backend/tests`): unit — скидка, разбор строк, проверка запросов; интеграционные на реальной PostgreSQL (`products_test`) — импорт файла-примера и повтор без дублей, плохие строки, битые картинки, CRUD и фильтры по HTTP, импорт через API → очередь → обработчик, вход и 401, сидер. Сеть и RabbitMQ не нужны: картинки — `MockHttpClient`, очередь — in-memory.
- **E2E** (`e2e/`): вход и guard; импорт файла-примера → поиск → карточка; отчёт по плохим строкам; отказ не-xlsx.
- **PHPStan** level 8 (с `phpstan-doctrine`) — без ошибок. **PHP CS Fixer** — PER-CS 2.0.
- **GitHub Actions** (`.github/workflows/ci.yml`): PHPStan, CS, PHPUnit на PostgreSQL; сборка фронта; сборка образов и e2e на поднятом стеке.

## Допущения

Задание оставляет часть решений на исполнителя. Что выбрано и почему:

| Вопрос | Решение |
|---|---|
| Какой столбец — `external_code` | «Внешний код». «Код» и «Артикул» — другое; «Артикул» в файле пустой |
| Куда идут ссылки на фото | «Доп. поле: Ссылки на фото» → `product_images` (несколько ссылок через запятую). В атрибуты не дублируются |
| «Доп. поле: Ссылка на упаковку» | Атрибут, как все «Доп. поле» |
| Пустые доп. поля | Не сохраняются |
| Названия товаров не уникальны | Ключ только `external_code` |
| Дубли кода внутри файла | Пишется первая строка, остальные — в ошибки |
| Битая картинка | Предупреждение; товар сохраняется, ссылка остаётся без `path` |
| БД | PostgreSQL |
| Брокер | RabbitMQ |
| Slim и Symfony Messenger | Slim + отдельные компоненты Symfony (Messenger, RateLimiter, HttpClient) без фреймворка, сборка через PHP-DI (`config/messenger.php`) |
| Индикатор прогресса «в карточке товара» | Полный — на странице импорта; в карточке — блок «Последний импорт» с прогрессом и отчётом |
| Пользователи | Один администратор из `.env`; таблица пользователей для задания избыточна |

В файле-примере две ссылки на фото (`SNL-558148_b15.jpg`, `SNL-575975_b11.jpg`) отвечают 403 у поставщика — они попадают в предупреждения отчёта.

## Структура

```
backend/
  config/          контейнер (PHP-DI), маршруты, Messenger, миграции
  src/Controller   тонкие контроллеры: разобрать запрос → сервис → JSON

  tests/           PHPUnit + тестовые xlsx

e2e/               Playwright

docs/              текст задания и файл-пример
```
